# Three.js Mixamo 角色導入

把使用者提供的模型、貼圖與動畫接到既有角色控制器。直接接受 FBX；不要求使用者先轉 GLB、不綁定角色名稱、檔名、動畫數量或課程環境。Idle／Run 只是站立／移動的一組對應，Walk、Jump、Attack、Dance、Death 等可依需求加入。不要為未要求的狀態自行增加玩法。

## 先確認專案與素材

- 讀現有場景、角色控制、動畫迴圈、資產路徑與 package.json；沿用 Three.js 版本及架構（原生 Three.js 或 React Three Fiber），不建立第二套 renderer／遊戲迴圈。
- 列出使用者提供的 FBX、貼圖及現有動畫。檔名只作線索；載入後讀實際 clips、duration、tracks、SkinnedMesh、骨架及材質。Mixamo 不同 FBX 的 clip 可能都叫 mixamo.com，不以該名稱當唯一識別。
- 選一份帶網格及骨架的 FBX 作主模型，其餘 FBX 提取動畫，不把每個 With Skin 模型都加到場景。若只有 Without Skin 動畫，先找現有相容角色；沒有時明確回報缺少模型，不生成假角色冒充完成。
- 用可擴充的資料對應語意狀態、資產 URL、clip 名稱或索引、loop、播放速度、淡入時間、完成後狀態及中斷規則。只有多個候選 clip 意義無法判斷才詢問；不要要求使用者把檔案重命名成固定格式。
- 不覆蓋原始素材或既有作品。新增檔案使用獨立目錄，資產 URL 遵循專案 base path，不寫入開發者本機絕對路徑。

## 模型與貼圖

使用專案版本相容的 `three/addons/loaders/FBXLoader.js`。現有版本若採 examples/jsm 路徑則沿用，不混裝不同版本 Three.js。載入失敗顯示可理解的缺檔訊息，保留原角色或安全停用新角色，禁止每幀重試下載。

以 LoadingManager／現有資產系統解析外部貼圖。若 FBX 包含失效本機路徑，建立已知貼圖對應，保留大小寫及 URL 編碼；同名貼圖有多個來源時不能任意取第一個。只讀使用者授權的素材，不自動存取 FBX 內任意遠端網址。瀏覽器端不可依賴 Node 檔案 API。FBX 載入 Promise 完成不代表貼圖完成；等待 LoadingManager 的相依資產完成及必要圖片解碼，再宣告可用或撤銷內嵌圖片的 blob URL。失敗也須清理資源，不能提早撤銷仍在載入的圖片來源。

先保留載入材質，再按 mesh／material 對應補貼圖，不把同一張顏色圖套到所有材質。顏色／自發光貼圖採專案版本的 sRGB 設定；normal、roughness、metalness 等資料貼圖維持非色彩處理。不要把 GLTFLoader 的 flipY 慣例直接套到 FBX，須依實際 UV 檢查。不得用全白材質或永久 DoubleSide 掩蓋缺圖、反面或 UV 問題。

以實測模型包圍盒及遊戲既有單位設定高度、腳底位置和前向；不要固定乘 0.01 或把每個模型都旋轉 180 度。在外層 visual group 做縮放與朝向校正，保留骨架 bind pose。物理碰撞器及位移由原控制器維持，不能由動畫骨架直接取代。

### 替換既有角色

先列出原角色附帶的名字、隊伍／玩家識別、手持物、武器掛點、碰撞器及鏡頭追蹤目標。換網格不能讓這些功能失效；保留識別訊號，不以任意染色破壞貼圖。沿用身體掛點或改接骨骼，須按物件用途決定，並在站立、移動、轉向及互動時檢查位置。手部骨骼掛點須換算縮放與朝向，避免雙重縮放；缺少持物動畫或 IK 時明示姿勢限制，不宣稱抓握已正確。

在實際遊戲鏡頭下比較移動距離、步頻與腳底接觸；先校正尺寸、位移來源及循環接縫，再視滑步調整動畫播放速度。不要為配合動畫擅改玩法速度，也不預設所有動畫適合速度縮放。

### 素材負擔

記錄實際下載大小、貼圖尺寸及同時顯示的角色數。多份 With Skin 素材提取 clip 後釋放不再使用的網格及貼圖；共用資源由擁有者釋放。先測目標裝置的首次載入與穩定幀時間，再決定是否需要精簡、壓縮或轉檔；保留原檔，不強制 FBX 轉 GLB，不把桌面窄視窗當成實體手機效能。

## 動畫相容性

同一角色從 Mixamo 下載的多份 FBX，先比較骨骼名稱、父子階層、rest/bind transforms 與尺度，再把各 clip 綁到主模型的 mixer。檢查每個 track 能解析到目標，沒有 PropertyBinding 警告。

- 不同 namespace 可以建立一對一映射，但須檢查重名衝突；不可全域刪除冒號／前綴後盲目播放。
- 同名骨骼不等於相同骨架。不同 bind pose／比例須透過已有可靠 retarget 流程，或依當前 Three.js 的 SkeletonUtils.retargetClip 建立並驗證映射；無法可靠處理就回報不相容，不把扭曲角色視為成功。
- 修改 clip／track 前 clone，避免污染快取及其他角色。
- 若 FBXLoader 提示每頂點超過四個蒙皮權重，記錄其裁減行為，確認當前 loader 是否已正規化權重，再檢查手肘、肩膀、髖部與膝蓋的變形。不能靜音警告後宣稱完全相容；若出現明顯破面，需修正權重或重新匯出並重測。
- 多角色用相容版本的 SkeletonUtils.clone 複製帶骨架模型，各自建立 mixer；普通 Object3D.clone 不能視為骨架獨立已驗證。

## 接上遊戲狀態

使用資料對應選擇 action，不寫成只有兩個固定動畫的元件。沒有設定的狀態回到已指定的安全 fallback；缺少必要動畫須指出，不能默默用另一動畫冒充。

站立／移動預設由角色控制器的「實際水平速度」決定，避免只看按鍵而在撞牆、失去焦點或停止移動後仍跑步。加入適合遊戲尺度的起跑／停止門檻（起跑門檻高於停止門檻）避免速度噪聲抖動。若遊戲刻意在碰牆時仍跑步則尊重既有設計。斜向移動遵循控制器既有速度規則，不因動畫重寫操作。

Idle、Walk、Run 等循環播放；Jump、Attack 等依玩法使用一次性或分段動畫；Death 可以停在最後一格。一次性動畫的優先級、中斷與結束回退由設定／現有狀態機控制，不能被每幀的移動判定蓋掉。finished 監聽要確認 action 仍是當前有效動作，處理中斷後到達的舊事件，離場移除監聽。

只在狀態真正改變時 reset／play／淡入，不每幀重設。重播一次性動作由明確事件觸發。切換前恢復目標 action 的 enabled、paused、effectiveTimeScale／weight；處理快速來回切換及尚未結束的 fade，避免多個殘留 action 累積權重。淡入可從約 0.15–0.25 秒開始，依實際結果調整。用既有迴圈傳入秒數更新 mixer 一次；暫停、背景恢復與 delta 上限沿用遊戲策略。

### Root motion 與位移

先觀察每個 clip 的 root／hips 平移。一般由遊戲控制器移動的角色採 in-place 動畫，避免遊戲與骨架各移一次。遇到帶 root motion 的檔案，先明確選擇「提取位移交給控制器」或「移除水平累積位移」。後者只處理辨識出的位移 track／水平分量，保留基準位置、垂直跳躍與骨盆起伏，不刪除所有 position tracks。對沿固定方向前進的循環，可按每個 key 的時間比例扣除首尾水平淨位移，保留週期性的左右擺動；這只適用已檢查的直線週期，不能套用到轉彎、跳躍或非線性路徑。比較處理前後腳步、首尾接縫與垂直起伏。轉向 root rotation 也須避免與控制器雙重套用。完整 root-motion 需求才實作碰撞相容的提取流程，不擅自改遊戲移動模式。

### 非同步與清理

模型載入完成前暫存所需狀態，完成後套用最新狀態。重試、換角色、卸載用 generation token／生命週期標記忽略過期結果，不能在舊場景再加入角色。離場停止 actions、uncache mixer root、解除事件及釋放本角色擁有的 geometry／material／texture；共享快取須計數或由快取管理，不誤釋放其他角色仍使用的資源。

## 驗收

先在隔離預覽或可還原場景驗證，再接回原遊戲；不要更改正式存檔或無關作品。執行驗收時讀 [驗收證據](references/acceptance.md)，依本次範圍記錄通過、失敗、阻塞或不適用及證據。不能將未執行項目列為通過；Skill 結構驗證、合成測試、實際遊戲與真機證據分開。

- 模型材質、完整手腳、大小、腳底與朝向正確，無缺圖、綁定警告、T pose 卡住或骨架扭曲。
- 靜止持續 Idle，移動持續 Run／已指定移動動作；放開操作返回站立，連續起停、斜向移動及碰撞符合既有玩法。
- 除 Idle／Run 外至少用已有的第三種動畫驗證映射與循環／單次設定；若沒第三個實際素材，只能用合成 clip 驗證控制邏輯，不能聲稱第三個 FBX 已測。
- 快速切換不重複觸發、無漂移／傳送；一次性完成及中斷回退正確，暫停／恢復不跳躍。
- 缺圖、缺 clip、載入失敗與離場後載入完成有合理處理；多角色骨架與動畫狀態互不干擾。
- 執行專案必要檢查及真實瀏覽器觀察。無實際 FBX、無瀏覽器或不能驗證時，分開回報已實作、靜態檢查與未實測部分；不可用編譯通過代替角色可玩。
